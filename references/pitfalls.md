# 已知坑（都是实盘踩过的）

## 1. `drive +search --mine` 不能当发现层

`--mine` / `--created-by-me` / `--edited-since` 只捞"用户本人碰过"的文档。

实测同一账号：三路搜索得 594 篇，全库遍历得 **4,098 篇**——漏掉 3,504 篇「有权限但不是本人创建」的。

用户说"我的飞书文档"时，他要的是所有能看到的，不只是他建的。

**正确做法：知识空间节点树 + 云空间文件夹树遍历为主，搜索只作补充。**

## 2. `wiki +space-list` 不返回个人文档库

官方 CLI 明确说明：底层 API 从不返回 `my_library`。

普通用户往往没建知识空间，文档全在"我的文档库"里。只遍历 `+space-list` 的结果，会**一篇都抓不到**。

**必须单独补一路：`--space-id my_library`。**

## 3. 飞书链接有两种域名，token 相同

```
https://www.feishu.cn/wiki/<token>
https://<tenant>.feishu.cn/wiki/<token>
https://<tenant>.larksuite.com/docx/<token>
```

同一篇文档可能以不同域名出现。**按域名判断会把同一篇算成两个节点，双链直接错乱。**

**正确做法：只解析 URL 里的 token，域名一律忽略。**

## 4. wiki 链接的 token 是 node_token，不是 obj_token

`/wiki/<node_token>` 和 `/docx/<obj_token>` 指向同一篇文档。

如果只拿 obj_token 建索引，正文里所有 wiki 链接都会变成"指向未知文档"。

**正确做法：先建 `node_token → obj_token` 映射，解析出的 token 先查映射再匹配。**

## 5. 旧版 `doc` 不能直接 fetch

新版 `docx` 用 `docs +fetch --doc-format markdown` 正常。
旧版 `doc` 需要 `drive +export --file-extension docx` 导出后解包提文本，否则静默返回空。

**判断方式**：`obj_type == "doc"` 走导出路线。

## 6. 无权限文档是静默失败的

`docs +fetch` 对无权限文档返回 error code `3380004`，但不同版本措辞不同。

如果只判断 `returncode != 0` 就重试，会把 3 次重试全浪费在必然失败的文档上。

**正确做法：错误信息里匹配 `permission` / `forbidden` / `not exist` / `3380004`，命中就直接标记 `deny`，不重试。**

## 7. 表格类文档不要抓内容

多维表格（bitable）常达百万行，电子表格可能有几十个 sheet。

抓内容会让同步从 20 分钟变成几小时，而且对"知识大脑"价值极低。

**正确做法：`sheet` / `bitable` / `slides` / `file` 只记元数据 + 链接，标记 `meta-only`。**

## 8. 全文 n-gram 抽出来的不是词

中文没有词边界，用 2–4 字 n-gram 做特征，在结构化文本上会切出大量碎片：

```
"本期客单价为 38 元"  →  价分 / 期为 / 本期客 / 单价分 / 客单价为
```

跨文档频次过滤也没用——固定句式会让碎片同样高频。

**正确做法：用作者手写的章节标题（`## xxx`）和短列表项做特征词。**
这些是人的显式标注，质量远高于算法切分。实测术语从「价分/期为」变成「客单价/填充率/复购」。

## 9. 标题不能当唯一键

实测 10,794 篇里有 564 组同名文档（"无标题" 95 个、"周报" 90 个）。

用标题做主键会直接覆盖。

**正确做法：`token` 做主键，标题只作展示。**

## 10. HTML 内嵌正文会让文件膨胀

1,000 篇 × 3,000 字 ≈ 10 MB；不截断的话 1 万篇能到 100 MB+，浏览器打不开。

**正确做法：默认截断到 3,000 字/篇，超长文档只存开头（覆盖 95% 的文档全文）。**

## 11. `docs +create` 用 bot 身份，同事看不到

飞书文档创建有两种身份：
- `--as user`：以用户本人身份创建，出现在他的"我的空间"，同事按正常权限可见
- `--as bot`：以应用身份创建，归属应用，同事往往看不到

**索引文档必须 `--as user`。**

## 12. 索引文档不幂等会堆出一堆副本

每次运行都 `+create`，跑十次就有十篇《知识大脑·索引》。

**正确做法：首次创建后把 `doc_token` 写进 `state.json`，之后一律 `+update --command overwrite`。**

## 13. 全量发现耗时随空间深度非线性增长

29 个知识空间、逐层递归，实测跑了 13 分钟还没完（单线程 BFS + 每个父节点一次 API）。

**优化方向**：空间之间并行、父节点列表结果缓存、`has_child=false` 不入队（已实现）。
目标压到 3 分钟内。若仍慢，先跑 `--space <名字>` 限定范围。

## 14. 代理会坑 Python 而不坑 Node

macOS 上系统代理配置错误时：
- `curl` / `lark-cli`（Node）**不读**系统代理，看起来一切正常
- Python `urllib` **会读**，立即 `Connection refused` / TLS EOF

**取数脚本一律加 `env no_proxy='*'`，或改用 subprocess 调 CLI，不要在 Python 里发 HTTP 请求。**
