# feishu-brain 设计说明

> 状态：待用户确认
> 最后更新：2026-10-18

---

## 1. 一句话定义

**把你飞书里的几百上千篇文档，变成一份不打开飞书也能查、能带走、能交给别人的知识大脑——一个 HTML 文件，双击就开。**

## 2. 目标用户

| 项 | 定义 |
|---|---|
| 是谁 | 普通飞书用户（运营、产品、销售、教师、创业者），不是工程师 |
| 语料量 | **默认按「语料充足」设计：1,000–5,000 篇**；低于 300 篇走降级模式（见 9.1） |
| 客户端 | **WorkBuddy / CodeBuddy**（内置飞书连接器，`lark-cli` 开箱可用） |
| 技术能力 | 不需要装任何东西，不需要写代码，不会用命令行也没关系 |
| 现有工具 | **不假设有任何笔记软件**（无 Obsidian / Notion / 有道云） |

## 3. 解决的三个痛点

| 痛点 | 症状 | 怎么解 |
|---|---|---|
| 找不到 | 飞书搜不到正文、标题大量重名、只记得"好像写过" | 本地全量索引 + 全文检索 |
| 说不清 | 存了一堆，但答不出"我到底懂什么" | 聚类分集 + 每条一句结论 |
| 带不走 | 换号、离职、权限变动，知识归零 | 落地单文件 HTML，脱离飞书 |

## 4. 明确不做（非目标）

- ❌ **不做 RAG 问答**。没有向量库，没有"跟我的文档对话"。
- ❌ **不做原文备份**。只保结构 + 结论 + 出处链接，不存全文。
- ❌ **不替代飞书**。大脑是只读视图，编辑仍在飞书。
- ❌ **不预置行业分类**。集从用户自己的语料里长出来，不写死"私域/电商/教育"。
- ❌ **不上传任何数据**。全程本地，产物是本地文件。
- ❌ **不做定时任务**。skill 是用户主动触发的，不是后台服务。

## 5. 用户视角的完整流程

```
① 用户说：帮我用飞书文档建个知识大脑
② skill 检查授权 → 确认范围（全部 / 指定空间 / 最近N年）
③ L1 体检（3–5 分钟）→ 给用户看：多少篇、多少字、多少重名、多少空壳
④ L2 分集（15–25 分钟）→ 给出 3–8 个集 + 文档归属，让用户确认/改名/合并
⑤ 生成 HTML → 用户双击打开，能搜、能筛、能跳原文
⑥ 生成飞书索引文档 → 写回飞书，同事点开就能看整个大脑目录
⑦ （可选）用户点某一集说"这集深挖一下" → L3 提炼该集的知识条目
```

**两个入口，各管一件事：**

| 入口 | 给谁用 | 优势 |
|---|---|---|
| `飞书知识大脑.html` | 自己 | 全文搜索、离线、能拷走 |
| 飞书索引文档 | 自己 + 同事 | 在飞书里可读可分享，点链接直接跳原文 |

**关键设计：第 ⑦ 步是可选的、按集点单的。** 因为 L3 全量跑上千篇要 1–3 小时，第一次用就卡在这，用户会直接放弃。必须先让他拿到能看的东西。

## 6. 四段技术流程

| 段 | 脚本 | 输入 | 输出 | 失败处理 |
|---|---|---|---|---|
| 拉取 | `fetch.py` | 飞书 token / 范围参数 | `raw/` 平铺纯文本（一篇一个 `.txt`）+ `manifest.jsonl` | 单篇失败记入 `errors.jsonl`，不中断 |
| 体检 | `inventory.py` | `raw/` + `manifest.jsonl` | `inventory.json` | 无 |
| 分集 | `cluster.py` | `inventory.json` + 标题摘要 | `sets.json`（集 + 归属） | 无法归类的进「未分类」，不硬塞 |
| 提炼 | `distill.py` | `sets.json` + 指定集 | `knowledge.json` | 无证据的条目标【缺】，不编 |
| 出脑 | `build_html.py` | 以上全部 | `飞书知识大脑.html` + 3 个 CSV | 无 |
| 建链 | `links.py` | `raw/` 正文 | `links.json`（边表 + 相似度） | 无内链的文档跳过，不报错 |
| 检索 | `search.py` | `raw/` + `sets.json` | 标准输出 markdown 表 | 无 |
| 回写 | `index_doc.py` | 以上全部 | 飞书索引文档（1 篇） | 写失败不中断，本地产物已可用 |

**拉取阶段的硬要求**
- 发现层必须遍历全量（云空间树 + wiki 节点树 + search 三路合并），不能只用 `--mine`（会漏掉"有权限但非本人创建"的文档）
- 元数据（token / 标题 / 空间 / 类型 / 创建更新时间 / 原文 URL）必须随正文一起落地，后续全靠它
- 本地格式统一为**平铺纯文本 + JSONL 清单**，不生成任何双链、目录树、笔记软件格式

## 7. 数据契约

### 7.1 HTML 内嵌数据结构

```json
{
  "meta": {
    "owner": "账号名",
    "generated_at": "2026-10-18T22:30:00+08:00",
    "doc_count": 1084,
    "char_count": 2860000,
    "stages_done": ["L1", "L2"]
  },
  "sets": [
    { "id": "S01", "name": "集名", "desc": "一句话说明这一集管什么",
      "doc_count": 312, "knowledge_count": 18 }
  ],
  "docs": [
    { "token": "abc123", "title": "文档标题", "type": "docx",
      "space": "空间名", "year": "2025", "chars": 3421,
      "set": "S01", "url": "https://xxx.feishu.cn/docx/abc123",
      "updated": "2025-08-12", "has_number": true, "is_meeting": false }
  ],
  "knowledge": [
    { "id": "S01-K01", "set": "S01", "title": "知识条目标题",
      "conclusion": "一句话结论",
      "detail": "展开说明（可选）",
      "evidence": "A", "sources": ["abc123", "def456"],
      "first_seen": "2024-03", "last_updated": "2026-09" }
  ]
}
```

### 7.2 三个 CSV

**`语料清单.csv`**（文档维度，一篇一行）
`token | 标题 | 类型 | 空间 | 年份 | 字数 | 是否会议 | 含数字 | 归属集 | 处理状态 | 原文链接`

**`知识总表.csv`**（知识维度，核心交付物）
`知识ID | 集号 | 集名 | 知识标题 | 一句话结论 | 证据等级 | 支撑文档数 | 代表来源标题 | 代表来源链接 | 首次出现 | 最近更新`

**`集清单.csv`**（集维度，进度与覆盖）
`集号 | 集名 | 覆盖文档数 | 覆盖字数 | 知识条数 | 证据覆盖率 | 状态 | 备注`

> 三个 CSV 统一 UTF-8 BOM，Excel / WPS 双击可直接开。

## 8. HTML 的功能范围

**必须有的：**
- 顶部搜索框（全文，搜标题 + 结论 + 正文摘要）
- 左侧集列表（带文档数 / 知识数）
- 筛选器：年份、文档类型、是否会议
- 两个 Tab：**知识**（卡片流，按集分组）/ **文档**（表格，可按字数排序）
- 点知识卡 → 展开详情 + 出处列表，点出处跳飞书原文
- 移动端能看（响应式）

**不要的：**
- 不联网、不请求任何外部接口（单文件纯离线）
- 不做登录、不做权限
- 不做图表可视化（除非后续确认需要）

## 8.5 飞书索引文档（写回飞书）

这是知识大脑的**第二个入口**。HTML 是给自己用的，飞书索引文档是给自己 + 同事看的。

| 项 | 规格 |
|---|---|
| 何时生成 | L2 完成后（没有集划分，索引没有价值） |
| 创建位置 | 默认「我的空间」根目录；用户可指定文件夹 token |
| 文档标题 | `<账号名>的知识大脑 · 索引` |
| 写权限 | **必须走 `--as user`**，以用户本人身份创建，不能用 bot（否则同事看不到） |
| 幂等 | 首次创建后把 `doc_token` 记进 `state.json`，之后重复运行**更新同一篇**，不重复新建 |

**文档内容结构：**

```markdown
# <用户名>的知识大脑 · 索引

> 语料：1,084 篇飞书文档 / 286 万字 / 2021–2026
> 生成：2026-10-18 22:40 ｜ 分 6 集
> 本地完整版：飞书知识大脑.html（含全文搜索）

## 一、这个大脑怎么用

- 想看某主题下我掌握什么 → 下面按集查
- 想找某篇原文 → 搜标题，或点知识条目后的「原文」
- 想知道结论有多可靠 → 看证据等级 A/B/C

## 二、集目录

### S01 流量变现与广告投放
> 覆盖 312 篇 / 46 万字 ｜ 已提炼 18 条

| 知识条目 | 一句话结论 | 证据 | 原文 |
|---|---|---|---|
| 阶段目标优先于单一指标 | ... | A | [链接] |
| 放量前先确认结算能力 | ... | A | [链接] |

### S02 ...

## 三、未分类文档（87 篇）
...
```

**生成规则：**
- 每个集一个二级标题，集下用表格列知识条目
- 表格「原文」列放飞书原始链接，点开直达
- 未分类文档单独一节，只列标题 + 链接，不做提炼
- 文档字数控制在 2 万字以内（飞书单文档性能边界）

## 8.6 双向链接（不借助任何第三方工具）

**实测前提**：飞书正文里的原生内链只覆盖 **20.9%** 的文档（1,910 篇样本中 400 篇有内链，569 条边，篇均 1.4 条）。所以双链必须分三层，覆盖度递增、可信度递减。

| 层 | 关系 | 覆盖 | 可信度标注 | 算法 |
|---|---|---|---|---|
| **L1 原生链接** | A 引用了谁 / A 被谁引用 | ~21% | **实测** | 正则解析正文 markdown 中的飞书文档链接，token 归一化 |
| **L2 知识回链** | 这篇原文贡献了哪几条知识 | 进过提炼的 100% | **实测** | 知识条目 `sources` 反查 |
| **L3 相似文档** | 内容相近的还有哪些 | 100% | **推断** | 关键词 TF-IDF 余弦，只展示 top 5 |

**硬规则：**
- L1 / L2 标「实测」，L3 必须显式标「推断」。不得让用户把算法猜的当成作者写的。
- 解析内链**只认 token，不认域名**。飞书链接有 `www.feishu.cn` 和 `<tenant>.feishu.cn` 两种写法，token 相同，按域名分会把同一篇算成两个节点。
- 反向索引在 HTML 前端用 JS 现算，不预生成，避免文件膨胀。

**HTML 中文档详情页的呈现顺序：**
```
标题 · 所属集 · 年份 · 字数
──────────────
正文摘录（≤3000 字）
──────────────
◀ 本文引用了 N 篇        （L1 实测）
▶ 被 N 篇引用            （L1 实测）
▣ 贡献了 N 条知识        （L2 实测）
≈ 相似 N 篇 · 推断       （L3 推断）
```

## 8.7 检索层（给 AI 用，不是给人用）

HTML 是静态快照，skill 是活的检索层。两者共用同一份本地语料。

新增 `search.py`：

```bash
python3 search.py --query "转化率 目标" --top 20
python3 search.py --query "周报" --set S01 --since 2025-01-01
```

- 输出 **markdown 表**（给 AI 读，不是给人看）：`得分 | 标题 | 日期 | 集 | 命中片段 | 原文链接`
- 支持关键词、集筛选、时间筛选、文档类型筛选
- 纯本地关键词检索，不做向量、不联网

**使用者问任何问题时，AI 的正确行为是：先 `search.py` 检索 → 再基于命中片段回答 → 附出处表。**
回答必须区分「语料里明确写了的」和「根据多条推断的」，语料里没有的就说没有。

## 9. 默认值与边界

### 9.1 小语料降级（兜底，不作为宣传口径）

主设计基准是**语料充足（1,000 篇以上）**。但如果用户只有两三百篇，强行分集会出现大量"未分类"，比不分集更糟。因此：

| 语料量 | 模式 | 行为 |
|---|---|---|
| ≥ 1,000 篇 | 标准 | 5–8 集，正常提炼 |
| 300–1,000 篇 | 标准 | 3–6 集，正常提炼 |
| < 300 篇 | **降级** | 不强行分集，改为「扁平索引 + 自动标签」；索引文档的「集目录」退化为「主题标签」 |

降级规则写死在 skill 里，不由用户判断。

### 9.2 其他默认值

| 项 | 默认 | 可改 |
|---|---|---|
| 拉取范围 | 全部有权限文档 | `--since 2024`、`--space 空间名` |
| 增量 | 按 `token + revision` 比对，只重拉变化的 | 支持 `--full` 全量重跑 |
| 集数量 | 按语料量自适应：100–300 篇 → 3–4 集；300–1,000 → 4–6 集；1,000+ → 5–8 集 | 用户可增删改 |
| 成集门槛 | 每集 ≥ 40 篇 **或** ≥ 5% 语料 | 可调 |
| 知识条目粒度 | 一句话结论 ≤ 60 字；详细说明 ≤ 300 字 | — |
| 证据等级 | A（原文明确写）/ B（多处可推出）/ C（单一或 AI 纪要）/ 缺（无支撑） | — |
| 隐私 | 全程本地；HTML 内嵌数据，提示用户"此文件含你的飞书内容，分享前确认" | — |

## 10. 验收标准

一个没用过的人拿到 skill 后，能做到：

- [ ] 说一句"帮我用飞书文档建个知识大脑"，无需额外配置即开始
- [ ] L1 在 5 分钟内给出体检结果
- [ ] L2 给出可读懂的集划分，且能改名/合并
- [ ] 双击 HTML 能打开，搜索任何关键词 3 秒内出结果
- [ ] 点任意知识条目能跳回飞书原文验证
- [ ] 全部产物在**一个文件夹 + 一个 HTML 文件**里，不依赖任何软件
- [ ] 换一台电脑，把文件夹拷过去照样能打开
